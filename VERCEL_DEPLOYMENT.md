# Vercel deployment preparation

The root `vercel.json` exposes the Next.js frontend at `/` and the Express API at `/api/*`; Express keeps its `/api/v1` prefix. The browser calls `/api/v1` on the same origin in production. There are no server-to-server calls between these services, so no service bindings are required. `NEXT_PUBLIC_API_URL` should be unset for the same-origin configuration; for standalone local development, frontend `.env` may keep the existing backend address.

Before enabling any deployment, set `DATABASE_URL`, `JWT_SECRET`, and `JWT_REFRESH_SECRET` as Vercel environment variables for each intended environment. Set `JWT_ACCESS_SECRET` if a separate access signing secret is desired. `API_PREFIX` must be `/api/v1` or unset. Existing non-Vercel browser origins can be supplied in `CORS_ORIGIN`, comma-separated. Do not place secrets in source control. Configure separate preview and production databases or otherwise prevent previews from modifying production data. Database schema provisioning and seed credentials are separate administrative operations; builds do not run migrations or seeds.

**Media storage:** Product photos and videos are stored in PostgreSQL in private, owner-scoped blocks. The browser uploads and downloads each file in 3 MiB pieces to stay below Vercel's 4.5 MB function payload limit. Existing local-only files require an explicit, verified migration before they can be displayed on Vercel. Media storage and repeated transfers use database capacity and can affect database cost and performance as the library grows; monitor capacity and consider private object storage at larger scale. Old local files remain available as a development fallback, not as Vercel storage.

To validate routing, install an up-to-date Vercel CLI and run `NEXT_PUBLIC_API_URL=/api/v1 vercel dev` from the repository root (this overrides the local frontend `.env` backend URL) after linking an appropriate Vercel project and configuring test environment variables. Verify `/api/v1/health`, sign-in, product listing, access control, and a complete media upload/download workflow using a separate test database and a separate test database. Deployment setup and media migration require separate confirmation.
